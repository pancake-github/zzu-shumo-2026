# 任务拆解与研究组织

用于读题、选题、研究设计及多问衔接。历史写作资料和跨年论文分类提供组织经验；当届题目、正式规则、用户要求及已有项目约定决定当前任务。历史题号和获奖数量不构成选题成功率。

## 按请求规模直接推进

已明确的任务直接完成授权范围内的工作。单句改写只给改写，已有结果整理不重新建模，局部图文调整只检查其影响范围；这些任务不启动完整研究流程。

遇到本技能已经覆盖的情况，按相应模块的默认方式处理，完成后简述重要取舍。普通的文件组织、连接词调整、图例位置等实现选择自行解决。可能改变研究对象、数学含义、数据用途或修改范围的缺失信息，先查题目、现稿和已有结果；仍无法确定时，将必要问题集中提出，并继续不依赖答案的工作。

用户明确要求逐阶段确认、只规划或只检查时，停在指定边界。否则按已授权目标连续推进，不在每个步骤后询问是否继续。保留用户已确认的参数和偏好，后续同类任务直接采用；新要求优先于旧默认。

## 读题后确定一条主线

先完整阅读任务和相关附录，辨认每问是描述、估计、解释、预测、评价还是优化。提取研究对象、时空范围、单位、约束，以及最终需要给出的数值、排序、机制或方案。

将内容区分为题目必答、支撑判断所需的验证、可选扩展。题目允许选择方法或情景时，围绕目标选定主路线及必要对照；继续核对后文是否明确要求比较、验证或外推，不能仅凭“可选”省去这些任务。新增分析应能回答具体问题、支撑关键判断或识别重要局限，不默认计算所有方法与参数的组合。

复杂赛题可用一张简表连接“小问—需要回答的内容—输入—方法—验证—输出”，也可沿用项目已有安排。只记录有用信息；不为填满表格编造数据或创建整套状态文件。选题优先比较数据可读性、团队能力、核心模型能否完成、验证是否可行，以及各问之间的依赖。

## 从可解问题到可写结果

先建立能够贯通输入、模型和输出的最小有效方案，确认主要约束与题目要求均能满足，再决定是否值得增加复杂度。基线可以是简单统计模型、现有方案、物理极限或小规模精确解，选择应服务实际比较。

每种模型说明其职责：主模型、基线、解释性对照或辅助处理。选模依据来自目标、数据结构和已有检验，不以方法数量作为工作贡献。研究对象发生变化时，例如从平均表现改为可达到的边界，应先重新说明对象、假设与验证目标，不能把这一变化当作修复不理想系数的排版处理。

按实际进度维护可复用结果，避免每次修订重算已核验内容。完整研究通常保留计算入口、关键结果和论文来源；是否需要独立 Notebook、DOCX 或其他文件由当前交付要求决定。Word 与 Notebook 是推荐起点，已有项目工具、模板和用户指定格式优先。

论文组织见 [论文写作](paper-writing.md)。研究推进时同步必要的模型定义、参数、图表和结果解释，摘要在主要结论稳定后凝练。跨问共享量保持含义、单位和来源一致；已有符号表或配置即可使用，不额外建立重复字典。并行工作按输入、输出与文件责任分工，合并时检查接口和比较条件。

## 常见情境的执行边界

| 触发情境 | 默认动作 | 需要另行处理的边界 |
|---|---|---|
| 用户要求减少篇幅或计算量 | 先保留必答内容和独有证据，再合并重复解释、表格及辅助推导 | 删除会影响关键结论或指定检验时，说明影响并给出更小范围方案 |
| 数据来自不同实验、时期或平台 | 按用途建立可比较样本，优先核查身份、单位、时间及来源性质 | 缺少的信息会改变入选对象或估计含义时，按 [数据处理](data-preparation.md) 处理 |
| 参数方向异常或验证结果较弱 | 保存实际结果，按 [模型验证](model-validation.md) 检查数据、公式和识别条件 | 改研究对象、模型机制或样本规则前，明确理由及与原任务的关系 |
| 新结果影响后续小问 | 更新真正依赖该结果的分析和文字，复用无关部分 | 只有依赖结论已经成立时，才推进下游计算；故障诊断不当作科学结果 |
| 用户已修改文件或指定当前稿 | 读取该版本，在其基础上定点修改并同步必要来源 | 来源冲突无法判定，或覆盖前文件再次变化时，先保留候选结果 |

## 时间和交接

按截止时间、资源和实际进度安排求解、验证、整合及页面检查，为最终运行和导出预留时间；不硬编码阶段比例或固定工时。

长任务只记录继续工作需要的信息：已完成结果、当前依据、未决问题和下一步。明确区分计划、已执行、核验通过和用户验收；用户要求阶段验收时遵守该节奏，不把一次通过解释为授权新增研究。
